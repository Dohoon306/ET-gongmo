# 기능 명세서 (초안)

> 상태: 초안 · 팀 검토 전
> 담당 A·B·C는 가칭입니다. 실제 이름은 회의에서 정합니다.

## 우선순위 기준

- **P0**: 데모 시나리오에 나오는 기능. 없으면 시연이 끊깁니다.
- **P1**: 시간이 남으면 합니다. 빠져도 시연이 됩니다.

## 카테고리 체계 (초안)

AI는 이 목록 **밖의 태그를 만들지 않습니다.** 겹침 계산이 이 목록의 ID 기준이기 때문입니다.

| 축 | 태그 |
|---|---|
| 분야 | 공모아뷰 분야 코드와 1:1로 맞춥니다. IT(`it`), 기획·아이디어(`idea`), 디자인(`design`), 미술·음악(`art`), 영상·사진(`video`), 문학·논문(`writing`), 네이밍·슬로건(`naming`), 마케팅(`marketing`), 취업·창업(`startup`), 서포터즈·기자단(`supporters`), 봉사·체험(`volunteer`), 기타(`etc`) |
| 직무 | 백엔드, 프론트엔드, 앱, AI·데이터, UI/UX, 기획 |
| 기술 | Java, Spring, Python, JavaScript, React, Kotlin, Figma |
| 수준 | 초보, 경험 있음, 숙련 |
| 목표 | 배우고 싶음, 포트폴리오, 수상 목표 |

**겹침 점수**: 두 대상의 태그 중 같은 태그 개수. 점수가 같으면 최신순으로 정렬합니다.

분야 축을 공모아뷰 코드에 맞춰 두면, 공모전 분야는 AI 없이 그대로 옮겨지고 사용자·방의 분야 태그와 바로 비교됩니다. 화면에는 짧은 이름(예: `IT`)을 보여 주고, 저장은 코드(`it`)로 합니다.

## 외부 API: 공모아뷰

> 2026-11-20에 직접 호출해 확인한 내용입니다. 안내 페이지: https://www.gongmoaview.com/about/open-data

공모아뷰는 REST API가 아니라 **MCP 서버**와 **RSS**를 제공합니다. 둘 다 가입이나 인증 키가 필요 없습니다.

### MCP 서버 (주로 쓸 것)

- 주소: `POST https://www.gongmoaview.com/mcp`
- 형식: JSON-RPC 2.0. 세션을 만들지 않고 `tools/call`을 바로 호출해도 동작합니다.
- 헤더: `Content-Type: application/json`, `Accept: application/json, text/event-stream`

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"search_contests",
           "arguments":{"type":"contest","field":["it"],"target":["univ"],"sort":"due","limit":20}}}
```

| 도구 | 입력 | 돌려주는 것 |
|---|---|---|
| `search_contests` | `q` 검색어, `type` (contest/outside/educate), `field[]` 분야 코드, `target[]` (kid/teen/univ/adult/biz), `area[]` 지역, `due` (3/7/30/month), `sort` (due/new/prize/sources), `fresh` (today/yesterday), `limit` (최대 20) | **지금 접수 중인** 공고 목록 |
| `get_contest` | `id` (공고 주소 `/contests/{id}-제목`의 숫자) | 공고 한 건의 상세 정보 |

**응답은 JSON 필드가 아니라 마크다운 텍스트**(`result.content[0].text`)라서 서버에서 파싱해야 합니다.

`search_contests` 한 줄 형식:

```
- {제목} — {유형} · {주최} · 마감 {YYYY-MM-DD} · 1등 {상금} · 출처 {N}곳 · {공모아뷰 링크}
```

상금 항목은 없을 수 있으니 앞에서부터 순서대로 자르지 말고, `마감`·`출처`·`https://` 같은 앞머리로 구분합니다.

`get_contest` 형식 (`- 키: 값` 줄 + 원문 링크 목록):

```
# {제목}
- 유형: 공모전
- 주최: 조달청
- 접수 기간: 2026-10-12 ~ 2026-11-22
- 대상: 누구나
- 분야: 게임/소프트웨어 · 문학/수기 · 영상/UCC
- 1등 상금: 200만원
- 공모아뷰 페이지: https://...
## 확인할 수 있는 곳
- 주최 측 원문: https://...
- 링커리어: https://...
```

`get_contest`의 분야는 코드가 아니라 원 사이트의 분야 이름입니다. 분야 태그는 **어느 분야 코드로 검색해서 나왔는지**를 기준으로 붙이는 편이 정확합니다.

### RSS (보조)

- 주소: `https://www.gongmoaview.com/rss.xml` (최대 10분마다 갱신)
- 최근 공고와 사이트 게시글(공모 인사이트, 공지사항)이 섞여 약 85건이 옵니다. 링크가 `/contests/`로 시작하는 항목만 공고입니다.
- 분야 정보가 없어서 추천에는 쓰기 어렵습니다. "새 공고 알림" 같은 추후 기능에 쓸 수 있습니다.

### 저장 방식 (결정)

> 2026-11-20 결정: 공모아뷰 데이터는 MySQL에 넣어 두고 진행합니다.

```
수집 스크립트 (수동 실행 또는 하루 1회)
  → 공모아뷰 MCP 호출 → 마크다운 파싱 → MySQL upsert (+ JSON 스냅샷 저장)
시드 스크립트 (복구용)
  → JSON 스냅샷 → 같은 upsert 로직 → MySQL
앱 (추천, 상세, 방 목록)
  → MySQL만 조회
```

이유: 마크다운 파싱을 수집할 때 한 번만 하고, 추천 정렬을 카테고리 JOIN으로 계산하며, 마감돼 공모아뷰에서 사라진 공모전(주인공 공모전 포함)도 남기고, 시연 중 외부 호출과 호출 제한을 피하기 위해서입니다.

```sql
CREATE TABLE contest (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  gongmoa_id   BIGINT NOT NULL UNIQUE,   -- 공모아뷰 공고 번호, upsert 기준
  title        VARCHAR(255) NOT NULL,
  type         VARCHAR(20),              -- 공모전 / 대외활동 / 교육·강연
  host         VARCHAR(255),
  start_date   DATE,
  end_date     DATE,
  target       VARCHAR(100),
  prize        VARCHAR(100),
  gongmoa_url  VARCHAR(500) NOT NULL,    -- 출처 표기용 (필수)
  source_url   VARCHAR(500),             -- 주최 측 원문, 지원 버튼 링크
  raw_text     TEXT,                     -- get_contest 원본 마크다운. 파싱 규칙이 바뀌면 다시 파싱
  fetched_at   DATETIME NOT NULL
);

CREATE TABLE contest_category (
  contest_id   BIGINT NOT NULL,
  category_id  BIGINT NOT NULL,
  PRIMARY KEY (contest_id, category_id)
);
```

- upsert는 `INSERT ... ON DUPLICATE KEY UPDATE`로 합니다.
- 마감된 공고는 지우지 않습니다. 추천에서는 `end_date >= CURDATE()`로 거릅니다.

추천 쿼리 (B-3):

```sql
SELECT c.*, COUNT(*) AS overlap
FROM contest c
JOIN contest_category cc ON cc.contest_id = c.id
JOIN user_category uc   ON uc.category_id = cc.category_id AND uc.user_id = ?
WHERE c.end_date >= CURDATE()
GROUP BY c.id
ORDER BY overlap DESC, c.end_date ASC;
```

### 이용 규칙

- 화면에 출처 **'공모아뷰'**를 밝히고, **공모아뷰 공고 링크를 그대로** 남깁니다.
- 지원·접수는 주최 측 원문에서 하도록 안내합니다. 공모아뷰는 공고를 주최하거나 접수하지 않습니다.
- 너무 자주 부르면 제한될 수 있습니다 (RSS 기준 10분에 한 번이면 충분하다고 안내). 시연 중에 매번 부르지 말고, **미리 한 번 수집해 DB에 저장**한 뒤 그 데이터를 씁니다.
- `search_contests`는 접수 중인 공고만 돌려줍니다. 마감된 공모전은 다시 받을 수 없으니 시연에 쓸 공모전은 스냅샷으로 꼭 보관합니다.
