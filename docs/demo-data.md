# 시연용 데이터 목록 (초안)

> 상태: 초안 · 팀 검토 전
> 시연 전에 DB에 시드로 넣어 둘 데이터입니다. 사용자와 방은 가상이고, 공모전은 공모아뷰에서 받은 실제 공고입니다.
> 장면 번호는 [기능 명세서](feature-spec.md)의 데모 시나리오 번호입니다.

## 1. 사용자

| 사용자 | 역할 | 카테고리 | 쓰이는 장면 |
|---|---|---|---|
| 새싹 | **페르소나**. 시연 중에 가입합니다 (시드에는 없음) | 장면 1에서 AI가 붙임 → `IT` `백엔드` `Java` `초보` `배우고 싶음` | 1~6 |
| 방장 김 | 방1 방장. 장면 5에서 이 사용자로 전환합니다 | `IT` `백엔드` `Java` `경험 있음` `포트폴리오` | 3, 5 |
| 방장 이 | 방2 방장 | `IT` `백엔드` `Spring` `숙련` `수상 목표` | 3 |
| 방장 박 | 방3 방장 | `IT` `앱` `Kotlin` `초보` | 3 |
| 방장 최 | 방4 방장 | `디자인` `UI/UX` `Figma` `숙련` | 3 |
| 팀원 정 | 방1 기존 팀원 | `IT` `프론트엔드` `React` `초보` `배우고 싶음` | 5 |
| 팀원 한 | 끝난 팀 팀원 (평가 대상) | `IT` `프론트엔드` `JavaScript` `경험 있음` | 6 |

장면 6을 위해 **새싹이 이미 속한 "끝난 팀"**이 필요합니다. 장면 1에서 새로 가입한 새싹과 같은 사용자여야 하므로, 둘 중 하나로 정합니다.

- **방법 1**: 가입 직후 서버가 새싹을 끝난 팀에 넣어 둔다 (시연 전용 처리)
- **방법 2**: 장면 6만 미리 만든 다른 계정(예: "새싹(작년)")으로 전환해서 보여 준다 ← 초안 추천

## 2. 공모전

공모전은 공모아뷰에서 받은 **실제 공고**를 씁니다 (B-1). 시드로 직접 만들지 않습니다.

**수집 방법**
- `search_contests`를 분야 코드별로 한 번씩 호출합니다: `type=contest`, `target=univ`, `limit=20`, 분야 `it` · `idea` · `design` · `video` · `marketing`
- 분야가 섞여 있어야 장면 2에서 IT 공모전이 위에 오고 디자인·영상 공모전이 아래로 가는 차이가 보입니다.
- 받은 결과는 `contests-snapshot.json` 같은 파일로 저장해 둡니다. 시연 당일 공모아뷰가 안 되면 이 파일로 DB를 채웁니다.

**주인공 공모전 고르기** (방 4개가 걸릴 공모전)

`search_contests`는 접수 중인 공고만 주고 공고는 매일 마감되므로, 지금 고르지 말고 **시연 1~2일 전에** 아래 조건으로 하나 고릅니다.

- [ ] 분야에 IT가 있다 (`field=it`로 검색해서 나온 공고)
- [ ] 대상에 대학생이 포함된다
- [ ] 마감일이 시연일보다 뒤다
- [ ] 제목만 봐도 개발 공모전인 게 바로 보인다 (예: 앱·SW·AI 서비스 개발)
- [ ] 팀 참가가 가능하다 (원문에서 확인)

고른 공모전의 **공모아뷰 공고 번호**를 시드 스크립트에 고정하고, 3번의 방 4개를 모두 이 번호에 연결합니다. 이 공모전은 스냅샷에서 빠지지 않게 따로 보관합니다.

## 3. 모집 방 (모두 주인공 공모전 소속)

새싹의 카테고리 `IT` `백엔드` `Java` `초보` `배우고 싶음` 기준으로 겹침 수가 **5 → 3 → 2 → 1**로 확실히 차이 나게 짰습니다.

| 방 | 방장 | 원하는 팀원 카테고리 | 새싹과 겹침 | 정원 |
|---|---|---|---|---|
| 방1 · 초보 환영! 백엔드 같이 배워요 | 방장 김 | `IT` `백엔드` `Java` `초보` `배우고 싶음` | **5** | 3명 (현재 2명: 김, 정) |
| 방2 · Spring 서버 개발자 구합니다 | 방장 이 | `IT` `백엔드` `Java` `Spring` `수상 목표` | 3 | 4명 |
| 방3 · 앱 서비스 같이 만들 분 | 방장 박 | `IT` `앱` `Kotlin` `초보` | 2 | 3명 |
| 방4 · 디자인 강한 팀, 개발자 1명 | 방장 최 | `IT` `UI/UX` `Figma` `숙련` | 1 | 4명 |

방1 정원을 3명으로 두면, 장면 5에서 새싹을 수락하는 순간 **모집 완료로 바뀌는 것**까지 보여 줄 수 있습니다.

## 4. 끝난 팀 (장면 6)

| 항목 | 값 |
|---|---|
| 팀 | "작년 캠퍼스 해커톤 팀" · 상태: 종료 |
| 팀원 | 새싹(작년), 팀원 한, 방장 김 |
| 평가 상태 | 새싹(작년) → 아무도 평가하지 않음. 시연 중에 팀원 한을 평가 |
| 팀원 한이 받은 기존 평가 | 방장 김이 남긴 평가 1개 (평가 후 요약이 바뀌는 것을 보여 주기 위해) |

## 5. AI 대체 응답

시연 중에 AI 응답이 늦거나 실패하면 X-3 공통 모듈이 아래 응답을 돌려줍니다.

| 기능 | 입력 | 대체 응답 |
|---|---|---|
| A-2 카테고리 부여 | "학교에서 자바로 과제 좀 해봤고, 서버 쪽을 해보고 싶어요. IT 공모전은 처음이에요" | `IT` `백엔드` `Java` `초보` `배우고 싶음` |
| C-3 참가 메시지 초안 | 새싹 → 방1 | "안녕하세요! 학교 과제로 Java를 써 봤고, 이번 공모전에서 백엔드를 제대로 배워 보고 싶어 지원합니다. 공모전은 처음이지만 맡은 부분은 끝까지 해내겠습니다." |
| B-2 공모전 분류 | 수집한 공모전 | 분야 태그는 AI 없이 붙으므로, 직무·기술 태그만 비워 둔 채로 저장 (주인공 공모전은 `백엔드` `프론트엔드` `초보` `배우고 싶음`을 수동으로 지정) |

## 6. 시연 전 확인할 것

- [ ] 시드를 넣는 스크립트 하나로 위 데이터가 전부 다시 만들어진다 (리허설 후 초기화용)
- [ ] 새싹으로 장면 3을 보면 방1 → 방2 → 방3 → 방4 순서로 나온다
- [ ] 장면 5에서 방장 김으로 전환하면 새싹의 요청이 보인다
- [ ] AI 키를 빼고 돌려도 처음부터 끝까지 시연이 된다
- [ ] 네트워크를 끊어도 공모전 스냅샷으로 장면 2가 된다
- [ ] 주인공 공모전이 아직 접수 중이다 (시연 당일 아침 확인)
- [ ] 공모전 상세 화면에 출처 '공모아뷰'와 공모아뷰 공고 링크가 보인다
